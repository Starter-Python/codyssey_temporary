#### 1. 가장 먼저 볼 GitHub: 8T SRAM Logic-PIM

이 저장소가 현재 확인한 것 중 **회로도와 SPICE netlist를 함께 제공하는 가장 직접적인 8T SRAM PIM 자료**입니다. 8T SRAM 두 셀의 read bit-line을 precharge한 다음, 저장된 값에 따라 방전시키는 방식으로 NOR/OR 연산을 구성합니다. AI MAC보다는 Boolean PIM의 구조·타이밍·RBL sensing을 이해하는 데 적합합니다.[1]

- 저장소: [In Memory Logic Operations with 8T SRAM cells][1]
- 회로도 원본: [`LOGICwithSRAM.sch`][2]
- SPICE netlist: [`LOGICwithSRAM.cir`][3]
- 보고서: [`FinalReport.pdf`][4]
- 라이선스: [GPL-3.0][5]

#### 2. 아날로그 PIM 확장용: 8T SRAM In-Memory DAC

이 자료는 8T SRAM 셀과 transistor sizing을 이용해 4-bit DAC 기능을 메모리 안에서 구현합니다. 완전한 VMM/MAC macro는 아니지만, 이전에 이야기한 **아날로그 방식 PIM의 input DAC, weight-dependent current, column summation**으로 발전시키기 좋은 출발점입니다.[6]

- 저장소: [8T SRAM Based In-Memory DAC for AI Acceleration][6]
- 회로도 원본: [`InMemDAC.sch`][7]
- SPICE netlist: [`InMemDAC.cir`][8]
- 회로도 PDF: [`InMemDAC_Schematic.pdf`][9]

#### 3. schematic과 layout 그림을 같이 보는 논문: SDP8T-IMC

이 논문은 local bit-line sharing, decoupled read/write path, Virtual-VSS write assist를 포함하는 8T SRAM IMC 구조를 다룹니다. **8T cell/IMC 회로 그림뿐 아니라 Figure 11에 제안 SRAM의 layout 그림까지 포함**되어 있습니다. 다만 Magic `.mag`나 GDS 같은 편집 가능한 layout source는 공개되지 않았고, Boolean IMC 및 BCAM 중심이라는 점은 고려해야 합니다.[10]

- 논문 전문: [Local Bit-Line Sharing Robust Dual-Port 8T SRAM With Virtual VSS for Energy-Efficient IMC][10]
- PDF: [TechRxiv PDF][11]

#### 4. 아날로그 MAC 흐름을 이해하기 좋은 논문

이 논문은 8×8 8T SRAM array에서 여러 RWL을 활성화하여 RBL의 charge-sharing으로 MAC 전압을 만들고, comparator 여러 개로 만든 MAC decoder가 이를 digital count로 바꾸는 구조를 제시합니다. **8T cell, 8×8 array, MAC decoder, comparator**가 모두 그림으로 설명되어 있어, 아날로그 CIM macro를 설계하려는 목적에 특히 잘 맞습니다.[12]

- 논문 HTML: [A Novel 8T SRAM-Based IMC Architecture for MAC-Derived Logical Functions][12]
- PDF: [arXiv PDF][13]

#### 5. 8T SRAM-CIM 주변회로 참고용 open-access 논문

이 논문에는 proposed 8T SRAM-CIM bit-cell, 전체 architecture, write driver, body-biasing schematic이 공개되어 있습니다. layout 그림이나 source 파일은 없지만, **8T cell과 주변회로를 어떻게 묶는지**를 빠르게 이해하기 좋습니다.[14]

- 논문: [Low-Power 8T SRAM Compute-in-Memory Macro for Edge AI Processors][14]

#### xschem + Magic 기준의 현실적인 결론

이번에 확인한 자료 중에는 **“8T PIM 전체 회로도 + xschem 원본 + Magic `.mag` 원본”을 모두 공개한 저장소는 없었습니다.** 따라서 실제 xschem/Magic 프로젝트를 시작한다면 다음 조합이 가장 현실적입니다.

1. [자료 1][1]의 PIM read/compute topology를 참고해 xschem에서 8T cell과 `RBL precharge → multi-RWL evaluate → sense/compare`를 재작성합니다.
2. [자료 2][6]의 in-memory DAC를 input encoding 또는 current-weighting 아이디어로 참조합니다.
3. [자료 3][10]의 layout figure를 보고 read/write port separation, local bit-line, virtual ground 배치 감각을 잡습니다.
4. Magic에서 Sky130 8T cell과 small array(예: 4×4 또는 8×8)를 layout하고, parasitic extraction 후 ngspice로 PVT/Monte Carlo를 검증합니다.

## 대화 2. 공개 8T PIM 회로 자료가 드문 이유와 추가 탐색 요청

### 사용자

> 마지막으로 한번만 더 찾아줄래?? 아니 PIM 회로를 만든 깃헙 자료가 없을 수가 있나? 너무 유명하잖아. 근데 왜 공개가 되어있지 않은거지? 개발자들의 코드는 다 공개하는데 전자공학도는 폐쇄적이야?

### 어시스턴트

맞아요. **PIM 회로 자료가 ‘없는’ 것은 아닙니다.** 다만 찾으시는 수준, 즉 **8T SRAM PIM 전체 회로도 + 수정 가능한 schematic + custom layout + PEX/검증 testbench**까지 한 저장소에 공개된 자료가 드문 것입니다. 앞선 검색 범위를 넓혀 보니, 공개는 주로 다음 세 층 중 하나에 집중되어 있었습니다.

| 공개되는 층위 | 실제 공개 사례 | 부족한 부분 |
|---|---|---|
| **회로도·SPICE 수준 8T PIM** | 8T logic-PIM, 8T in-memory DAC | 대개 layout source 없음 |
| **논문 figure 수준 8T PIM** | SDP8T-IMC, 8×8 MAC IMC, 8T CIM 논문 | Cadence/xschem/Magic 원본 비공개 |
| **RTL·generator·backend flow 수준 PIM** | OpenACM | custom 8T analog bitcell 자체는 포함하지 않음 |

### 다시 찾은 것 중 실제로 쓸 만한 자료

#### 1. 가장 직접적인 **8T SRAM PIM 회로 소스**

[**rahulearn2019/Mixed-Signal-Circuit-Design-and-SImulation-Marathon**][15]은 8T SRAM 두 셀의 RBL을 precharge한 뒤 방전시켜 **NOR/OR 연산을 메모리 안에서 수행**하는 logic-PIM 프로젝트입니다. 단순한 발표자료가 아니라 eSim 회로도 원본과 SPICE netlist를 제공합니다. 지금 단계에서 실제 회로를 열어 보거나 8T read port를 수정해 보고 싶다면 이것이 제일 가깝습니다.[15]

- 회로도: [`LOGICwithSRAM.sch`][16]
- Netlist: [`LOGICwithSRAM.cir`][17]
- 회로 동작 설명: [`FinalReport.pdf`][18]
- 라이선스: [GPL-3.0][19]

다만 **eSim schematic**이라 xschem에서 바로 열 수는 없고, 구조를 보고 xschem으로 다시 그려야 합니다. `.mag`, GDS, LEF/DEF는 없습니다.

#### 2. 아날로그 PIM으로 확장하기 좋은 **8T In-Memory DAC**

[**abhash2205/8T-SRAM-Based-In-Memory-DAC-for-AI-acceleration**][20]은 8T SRAM cell의 weight-dependent conductance와 transistor sizing을 이용해 in-memory DAC를 구성합니다. 이 역시 전체 neural-network MAC macro는 아니지만, **input encoding과 current-weighted column 동작**을 시작하기에는 좋은 실제 회로 소스입니다.[20]

- 회로도: [`InMemDAC.sch`][21]
- Netlist: [`InMemDAC.cir`][22]
- 회로도 PDF: [`InMemDAC_Schematic.pdf`][23]

#### 3. **schematic과 layout 그림을 함께** 보려면

[**Local Bit-Line Sharing Robust Dual-Port 8T SRAM With Virtual VSS for Energy-Efficient IMC**][24] 논문이 가장 좋은 자료입니다. 8T SRAM cell, local bit-line sharing, read/write decoupling, Virtual-VSS write assist를 포함한 Boolean IMC 구조를 보여 줍니다. 또한 **Figure 11에 65 nm UMC 기준 proposed SDP8T의 layout 그림**도 있습니다.[24]

이것은 **완성된 EDA 소스**가 아니라 논문 그림입니다. 즉 Magic `.mag` 파일을 다운로드할 수 있는 것은 아니지만, 8T PIM cell의 transistor 배치와 routing 방향을 참고하기에는 가장 낫습니다.

#### 4. MAC 전압과 comparator decoder까지 보려면

[**A Novel 8T SRAM-Based In-Memory Computing Architecture for MAC-Derived Logical Functions**][25]은 8×8 8T SRAM array에서 multi-row RWL activation과 RBL charge-sharing으로 MAC 전압을 만든 뒤, 8개의 comparator로 구성한 MAC decoder가 count를 읽는 구조를 자세히 설명합니다. 8T cell, array, precharge, decoder, comparator 회로 그림이 모두 있습니다.[25]

#### 5. ‘PIM 코드가 공개되지 않는다’의 반례: OpenACM

[**OpenACM**][26]은 SRAM 기반 approximate **digital CIM**을 위한 공개 compiler/generator입니다. SRAM/processing-element generator, RTL template, SPICE 기반 transistor sizing, OpenROAD backend flow를 Apache-2.0으로 공개합니다.[26] 다만 이 프로젝트의 SRAM은 behavioral 6T model과 digital flow 중심이어서, 8T analog CIM bitcell의 custom schematic/layout을 가져다 쓸 수 있는 것은 아닙니다.

또 하나의 중요한 반례는 [**VIT의 8×8 6T SRAM IMC 프로젝트**][27]입니다. 이 프로젝트는 Cadence Virtuoso 기반 6T IMC의 schematic 이미지, layout segment, SPICE template, Verilog, 보고서를 **MIT 라이선스**로 공개했습니다.[27] 8T가 아니라는 한계는 있지만, `6T cell → 8T decoupled read-port cell`로 바꾸고 PIM periphery를 재사용하는 출발점으로는 매우 좋습니다.

### 왜 이런 자료가 드물까?

전자공학도가 특별히 폐쇄적이라기보다는, **공개해야 하는 ‘소스’의 성격이 소프트웨어와 다르기 때문**입니다. 물론 소프트웨어도 상용 코드는 대부분 비공개이고, 오픈소스가 강한 생태계가 별도로 형성되어 있는 것입니다.

첫째, PIM의 핵심 가치가 바로 **custom bitcell, sense path, reference/calibration, layout parasitic**에 있습니다. 논문 속 성능 차이는 종종 algorithm보다 transistor sizing, RBL capacitance, layout matching, ADC offset calibration에서 나옵니다. 따라서 연구실이나 회사가 관련 특허·후속 논문·spin-off를 준비한다면 raw source를 바로 공개하기 어렵습니다.

둘째, 회로는 schematic 하나만 있어도 재현되지 않습니다. 실제로는 PDK model, device corner, DRC/LVS rule deck, parasitic extraction, testbench, Monte Carlo setup, 라이브러리 버전이 함께 있어야 합니다. 과거 대부분의 commercial PDK와 Cadence 기반 environment는 NDA·라이선스 제약 아래에 있었습니다. Sky130처럼 공개된 PDK가 이 장벽을 낮추고 있지만, 공식 문서도 현 공개 PDK를 experimental preview로 설명하고 test chip·초기 검증 용도를 중심으로 안내합니다.[28]

셋째, 논문 출판의 관행도 다릅니다. 회로 논문은 보통 **cell schematic, macro block diagram, layout micrograph, PVT/Monte Carlo, measured result**를 공개하면 검증 가능한 것으로 취급해 왔고, GitHub에 edit 가능한 Cadence database까지 올리는 문화는 아직 약합니다. 반면 RTL, compiler, DNN mapping, architecture simulator는 설치와 재현이 쉬워 상대적으로 더 자주 공개됩니다. OpenACM 같은 프로젝트가 바로 그 방향입니다.[26]

즉, **공개 PIM은 존재하지만 ‘source의 레벨’이 다릅니다.** 대형 산업·학술 PIM macro의 layout source가 특히 희소하고, 학생 프로젝트나 6T 디지털 PIM은 훨씬 더 공개적입니다. 그래서 현재 가장 현실적인 경로는 `8T PIM topology/회로 source`는 자료 1·2에서 얻고, `8T layout 방향`은 자료 3에서 얻으며, `open-source PDK flow`로 xschem·Magic에서 직접 재구현하는 것입니다.
