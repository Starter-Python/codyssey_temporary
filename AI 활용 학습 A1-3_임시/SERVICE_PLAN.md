# 서비스 기획서 — 온기록

## 1. 서비스 개요

**온기록**은 사용자가 지금의 상태와 확보한 시간을 짧게 입력하면, AI가 오늘 바로 시도할 수 있는 **3단계 회복 루틴 초안**을 제안하는 웹 서비스다. 복잡한 마음을 해결해야 한다는 압박보다, 현재 가능한 가장 작은 행동을 고르는 경험을 우선한다.

| 항목 | 기획 내용 |
|---|---|
| 서비스 목적 | 바쁜 일상에서 자신의 상태를 짧게 점검하고, 실행 가능한 회복 행동으로 번역하도록 돕는다. |
| **타겟 사용자** | 과제·업무·일정 사이에서 잠시 멈추고 싶지만 무엇부터 해야 할지 정하기 어려운 학습자 및 직장인 |
| 사용자 문제 | 피곤하거나 긴장된 상태에서도 ‘쉬어야 한다’는 사실만 알고, 제한된 시간에 어떤 행동을 할지 결정하기 어렵다. |
| 서비스 가치 | 감정·시간·원하는 감각을 입력하면 5/15/30분 안에 수행 가능한 세 단계로 행동을 구체화한다. |
| 서비스 성격 | 의료·심리 진단 서비스가 아닌 일상적 웰니스 루틴 제안 도구 |

> **핵심 문장:** 오늘의 에너지를, 오늘의 속도로 정리한다.

## 2. 페이지·섹션 구성과 메뉴 이동

한 화면 안에서 자연스럽게 읽히되, 상단 메뉴로 즉시 이동할 수 있도록 4개 이상의 독립 섹션을 설계했다. 모바일에서는 메뉴가 접힘 메뉴로 전환되어 좁은 화면에서도 탐색이 가능하다.

| 메뉴/섹션 | 역할 | 사용자의 주요 행동 |
|---|---|---|
| 첫 장 (`#home`) | 서비스의 목적과 주의사항을 제시하는 도입부 | 루틴 설계 CTA 선택 |
| 루틴 설계 (`#routine`) | AI 기능이 동작하는 핵심 화면 | 상태·시간·원하는 감각·선택 메모 입력 후 결과 확인 |
| 사용 방법 (`#method`) | 입력이 루틴으로 바뀌는 과정을 설명 | 세 단계의 동작 구조 이해 |
| 온기록 소개 (`#about`) | 서비스 대상과 기술적 성격을 설명 | 첫 장으로 이동하거나 서비스 맥락 확인 |

## 3. AI 기능 상세 설계

### 3.1 입력과 출력

사용자는 상태, 확보 시간, 원하는 감각을 필수로 선택하고 200자 이내의 메모를 선택적으로 남긴다. 브라우저의 JavaScript가 입력값을 JSON으로 만들고 `fetch('/api/recommend')`로 전송한다. Python 서버리스 함수는 입력을 검증한 뒤, 서버의 환경 변수에서만 읽은 API 키로 AI 응답을 생성한다. 최종 결과는 제목, 짧은 안내 문장, 정확히 세 개의 행동 단계, 조정 안내로 구성되어 화면에 표시된다.

| 단계 | 입력/처리 | 출력/사용자 가치 |
|---|---|---|
| 1 | 상태·시간·원하는 감각 선택 | 오늘의 제약 조건을 스스로 확인한다. |
| 2 | JavaScript가 JSON `POST` 요청 전송 | API 키를 브라우저에 노출하지 않고 서버에 전달한다. |
| 3 | Python이 입력 길이·필수값·시간 범위를 검증 | 잘못된 입력을 AI 호출 전에 차단한다. |
| 4 | AI가 3단계 루틴 JSON 초안을 생성 | 막연한 휴식을 구체적인 작은 행동으로 바꾼다. |
| 5 | JavaScript가 결과를 DOM에 안전하게 렌더링 | 사용자는 한 단계만 골라 실천할 수 있다. |

### 3.2 실패 처리 기준

AI 기능은 결과를 보여 주는 것만큼 실패 상황을 명확히 안내해야 한다. 온기록은 다음 경우에 사용자가 다음 행동을 알 수 있는 메시지를 표시한다.

| 상황 | 감지 위치 | 사용자 안내 | 재시도 방식 |
|---|---|---|---|
| 필수 입력 누락 | 브라우저 폼 검증 | “현재 상태, 시간, 원하는 감각을 모두 골라주세요.” | 누락된 첫 항목에 포커스 이동 |
| 4xx 입력 오류 | Python API | 입력 형식 또는 필수값을 확인해 달라는 메시지 | 선택값을 수정해 재전송 |
| API 인증·서비스 오류 | Python API | AI 설정 또는 서비스 연결 상태를 확인하도록 안내 | 잠시 후 재시도 |
| 요청 과다(429) | Python API | 요청이 많으니 잠시 기다려 달라는 메시지 | 잠시 후 재시도 |
| 네트워크 지연 | JavaScript 12초 타이머 | 응답이 늦어지고 있다는 메시지 | 페이지를 유지한 채 재시도 |
| 모델 응답 형식 오류 | Python JSON 검증 | 결과 정리에 실패했다는 메시지 | 재시도 |

## 4. 사용자 경험 원칙

결과를 ‘처방’이 아닌 ‘초안’으로 부르고, 사용자는 단계 전체가 부담스러우면 하나만 선택하도록 안내받는다. AI 프롬프트에도 진단·치료·약물 조언을 하지 않도록 제한하고, 위기나 자해·타해 신호가 보이면 루틴을 대신 제시하지 않고 즉시 주변 사람과 지역의 전문·응급 도움을 찾도록 안내하도록 명시했다.

## 5. 기술 구조

프론트엔드는 프레임워크 없이 `index.html`, `styles.css`, `app.js`로 구성했다. Vercel은 프로젝트 루트의 `api/` 디렉터리에 있는 Python 파일을 파일 기반 함수로 제공하며, 해당 파일은 라우트에 매핑될 수 있다. [1] Gemini의 공식 Python SDK는 `GEMINI_API_KEY` 환경 변수를 사용해 Interactions API를 호출할 수 있다. [2] API 키는 브라우저 코드에 넣지 않고 서버의 환경 변수 또는 키 관리 서비스에서 읽어야 한다는 공식 보안 지침을 따른다. [3]

```text
[사용자 브라우저]
    └─ HTML 폼 입력
         └─ app.js: fetch('/api/recommend', POST JSON)
              └─ Vercel Python Function: api/recommend.py
                   ├─ 입력 검증·길이 제한
                   ├─ GEMINI_API_KEY 환경 변수 읽기
                   └─ Gemini Interactions API 호출
                        └─ JSON 결과 반환 → 화면 렌더링
```

## 6. 선택 보너스 기능

온기록에는 **고요한 화면 모드(다크 모드)**와 절제된 진입·버튼 모션을 적용했다. 사용자의 선택은 브라우저 `localStorage`에만 저장되며, `prefers-reduced-motion`을 존중해 모션 민감 사용자는 불필요한 애니메이션 없이 서비스를 사용할 수 있다.
