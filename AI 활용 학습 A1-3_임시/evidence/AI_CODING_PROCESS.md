# AI 코딩 도구 사용 증빙 기록

## 사용 목적

이 과제에서는 AI 코딩 도구를 단순 코드 생성기가 아니라, **기획을 화면·기능·문서로 구체화하고 오류 점검 기준을 만드는 협업 도구**로 사용했다. 실제 제출 시에는 이 기록과 함께 대화 화면 또는 작업 과정 스크린샷을 추가한다.

## 대화·작업 흐름 요약

| 단계 | AI 코딩 도구에 요청한 내용 | 사용자가 검토·결정한 내용 | 산출물 |
|---:|---|---|---|
| 1 | A1-3 과제 문서의 필수 요구사항 추출 | 프레임워크 금지, Python API, Vercel, 증빙 등 누락 방지 | 요구사항 목록 |
| 2 | 차별화된 AI 웹 서비스 아이디어 설계 | ‘감정 진단’ 대신 ‘회복 루틴 초안’으로 범위 축소 | 온기록 기획 |
| 3 | 3개 이상 이동 가능한 화면 구조 제안 | 한 페이지 4개 섹션 + 메뉴 이동 선택 | HTML 정보 구조 |
| 4 | 모바일을 고려한 바닐라 CSS 설계 | 편집형 비대칭 레이아웃과 접힘 메뉴 선택 | `styles.css` |
| 5 | 입력→AI API→결과 출력 흐름 구현 | 빈 입력·지연·API 오류를 별도 안내하도록 결정 | `app.js`, `api/recommend.py` |
| 6 | API 키 노출 위험 점검 | 키를 코드가 아닌 Vercel 환경 변수에서 읽도록 확정 | `.env.example`, `.gitignore` |
| 7 | 배포·검증 문서 작성 | 실제 URL과 캡처는 배포 후 채움 | README·체크리스트 |

## 오류를 이해하고 수정한 사례

| 확인한 문제 | 원인 분석 | 수정 방향 |
|---|---|---|
| 브라우저에 API 키를 두면 누구나 개발자 도구에서 볼 수 있음 | 프론트엔드는 사용자 기기에서 실행되므로 비밀값을 숨길 수 없음 | Python 서버리스 함수가 키를 환경 변수에서 읽도록 분리 |
| 필수 입력이 비어도 AI 요청을 보내면 비용과 오류가 늘어남 | 입력 검증이 서버에만 있으면 불필요한 네트워크 요청이 발생 | JavaScript에서 먼저 확인하고, Python에서 한 번 더 검증 |
| AI 출력 형식이 매번 일정하지 않을 수 있음 | 생성 모델의 텍스트는 형식이 흔들릴 수 있음 | JSON 형식 지시 후 Python에서 JSON·3단계 여부를 재검증 |
| 모바일에서 데스크톱 컬럼을 유지하면 폭이 좁아짐 | 고정 열 레이아웃은 작은 화면에서 읽기 어려움 | CSS 미디어 쿼리로 한 열과 접힘 메뉴로 전환 |

## 실제 제출 전 추가할 스크린샷

1. 과제 문서를 읽고 기획·코드 구조를 논의한 대화 화면
2. AI가 생성한 초기 화면을 검토하고 수정 방향을 지정한 대화 화면
3. 오류·보안·배포 점검을 논의한 대화 화면

> 스크린샷에는 API 키, 개인 식별 정보, 대화의 불필요한 민감 정보가 보이지 않도록 가린다.
